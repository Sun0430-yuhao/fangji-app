# 方剂学 · 微信小程序迁移计划

**目标**：在微信内同时覆盖安卓 / 苹果用户，复用现有学习逻辑与方剂数据，降低「无 Mac 无法出 iOS 包」的阻塞。  
**现状工程**：`fangji-app`（Vue3 + Vite + Vant4 + Pinia + vue-router + Capacitor + PWA）  
**推荐技术路线**：**uni-app（Vue3）→ 微信小程序**（可选后续再编 H5，与现网 PWA 并存）  
**原则**：逻辑尽量搬、UI 按小程序重做；**现有安卓 APK / PWA 继续维护**，小程序为并行产品线，不是替换开关。

---

## 1. 结论摘要

| 问题 | 结论 |
|------|------|
| 能不能上微信实现安卓+苹果通用？ | **能**（在微信内通用） |
| 能不能原工程一键变小程序？ | **不能** |
| 最划算做法 | **uni-app 新工程 + 抽离共享核心逻辑** |
| 预估工期（1 人熟手） | **MVP 2～3 周**；对齐现网功能 **4～6 周** |
| 与 APK/PWA 数据 | 默认**不互通**；靠导出 JSON 或后期账号云同步 |

## 2. 目标与非目标

### 2.1 目标（小程序 MVP）

- 首页今日任务（背诵/刷题目标可调）
- 章节列表 → 详情
- 背诵三卡型：翻面 / 选方名 / 歌诀挖空；忘记本轮重插
- 刷题 + 错题本（答对自动移出）
- 收藏、我的进度、本地重置
- 方剂数据本地打包（`formulas.json`），支持拼音搜索（评估包体积后决定是否全量拼音库）

### 2.2 非目标（首期不做）

- 小程序内嵌现有 H5（web-view）作为主方案
- 与安卓 APK 实时云同步
- 支付、社交分享裂变、订阅消息（可二期）
- 一次同时发 App Store 包（仍走另线）

### 2.3 并行产品关系

```
同一套「学习规则 + JSON 数据」
        │
        ├─ 现网：Vue H5 / PWA / Capacitor APK   ← 继续服务安卓安装包用户
        │
        └─ 新线：uni-app 微信小程序            ← 服务微信内安卓+苹果用户
```

## 3. 技术选型

### 3.1 推荐：uni-app（Vue3 + Vite）

| 优点 | 说明 |
|------|------|
| 语法接近现有 Vue3 | 学习曲线低 |
| 官方微信工具链成熟 | 审核、真机调试文档全 |
| 可再出 H5 | 与 PWA 策略可合流 |
| 组件生态 | uView / uni-ui 等可替代 Vant |

### 3.2 备选

| 方案 | 适用 | 不选原因（对本项目） |
|------|------|----------------------|
| Taro（React） | React 团队 | 现团队是 Vue |
| 原生小程序 | 极致控制 | 复用差、工期长 |
| web-view 套现网 | 快速演示 | 主体/域名/审核限制多，体验像网页 |

### 3.3 账号与合规（并行启动）

1. 注册微信小程序（个人或企业主体）
2. 类目建议：**教育 → 在线教育 / 教育工具**（以微信后台可选为准）
3. 准备：隐私政策、用户协议简版（本地存储说明）
4. 若仅本地数据、无用户登录：隐私条款写清「学习进度存本机」

## 4. 现有模块迁移映射

### 4.1 可高复用（建议抽到 `packages/core` 或 `shared/`）

| 现模块 | 内容 | 小程序侧 |
|--------|------|----------|
| `store.js` 核心算法 | SM-2 简化、`buildDeck`、今日目标、错题增删、导入导出结构 | **几乎原样**；存储改为适配层 |
| `corrections.js` | 名称/出处修正 | 原样 |
| `public/data/formulas.json` | 方剂库 | 放入小程序包内或分包 |
| 题型/挖空/选方名逻辑 | `StudyView` / `QuizView` 内纯函数 | 抽成 `studyCards.js` / `quizBuilder.js` 共用 |

### 4.2 需重写（UI / 平台 API）

| 现模块 | 原因 | 小程序替代 |
|--------|------|------------|
| 全部 `views/*.vue` + Vant | 组件不是小程序组件 | uni 页面 + uni-ui / 自研 |
| `vue-router` | 小程序页栈模型不同 | `pages.json` + `uni.navigateTo` |
| `localStorage` | 非浏览器 | `uni.setStorageSync` |
| `window.prompt`（目标自定义） | 小程序无 window | `uni.showModal` + input 或自定义弹层 |
| `fetch('data/...')` | 包内应用 `import` / 本地路径 | 构建期 import JSON 或 `uni.request`（若放 CDN） |
| `ProfileView` 导出下载 / 文件选择 | 无随意写文件 | 「复制 JSON 文本」+「粘贴导入」；或用微信文件能力（二期） |
| `native-back.js` / Capacitor | 无关 | 删除；用小程序返回键行为 |
| PWA / Service Worker | 无关 | 删除 |
| `pinyin-pro` | 包体积可能偏大 | MVP 可先汉字搜索；二期再加拼音或精简词典 |

### 4.3 页面 ↔ 小程序页面规划

| 现路由 | 小程序 path | Tab |
|--------|-------------|-----|
| `/` | `pages/home/index` | 学习 |
| `/study` | `pages/study/index` | 背诵 |
| `/quiz` | `pages/quiz/index` | 刷题 |
| `/profile` | `pages/profile/index` | 我的 |
| `/chapter/:id` | `pages/chapter/index?id=` | 非 Tab |
| `/formula/:id` | `pages/detail/index?id=` | 非 Tab |
| `/wrong` | `pages/wrong/index` | 非 Tab |
| `/favorites` | `pages/favorites/index` | 非 Tab |

Tab 栏：学习 / 背诵 / 刷题 / 我的（与现 App 一致）。

## 5. 架构设计（目标态）

```
fangji-learning/
  packages/
    core/                 ← 与平台无关
      formulas.json
      corrections.js
      memory.js           ← 从 store 抽出的算法
      quiz.js
      cards.js            ← 翻面/选方/挖空 enrich
      types.js
  apps/
    web/                  ← 现有 Vite 工程（逐步改为依赖 core）
    mp-weixin/            ← uni-app 微信小程序
```

**过渡策略（降低风险）**：

- **阶段 A**：先新建 uni-app，**复制** `store` 算法与 JSON，尽快出可审 MVP。  
- **阶段 B**：再抽 `packages/core`，让 web 与 mp 共用，避免长期两套逻辑分叉。

首期若人力紧，允许「先复制后抽离」，但计划中要留阶段 B，否则背诵规则改两次。

## 7. 关键风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| 主包体积超限（JSON + 拼音库） | 无法预览/提审 | JSON 分包；拼音二期或精简；图片压缩 |
| Vant 习惯难迁移 | 工期膨胀 | 先用 uni-ui 等价组件，不追求 1:1 视觉 |
| 审核类目/内容 | 拒审 | 提前选对教育工具类；避免医疗诊疗承诺文案 |
| 两套逻辑分叉 | 改规则改两次 | 阶段 5 抽 core；短期改规则以文档同步 |
| 导出导入体验差 | 用户换机丢进度 | MVP 用「复制/粘贴 JSON」；说明与 APK 导出格式兼容 |
| `pinyin-pro` 过大 | 包体积 | MVP 仅汉字匹配 name/herbs/function |
| 个人主体能力限制 | 部分接口不可用 | 功能已偏本地，影响小；传播用二维码 |

## 10. 里程碑与决策点

| 里程碑 | 决策 |
|--------|------|
| M0 工程可预览 | 确认 uni-app 而非原生 |
| M1 逻辑跑通 | 确认存储 Key 与 web 备份格式兼容 |
| M2 真机主路径通 | **是否提审 MVP** 还是对齐三卡型再提 |
| M3 正式发布 | 是否启动 `packages/core` 抽离 |
| M4（并行） | PWA 是否继续作为无微信用户的补充 |

**建议决策**：先 **M2 极简提审** 抢苹果微信用户，再迭代三卡型；或一次对齐现网再提审（更稳、更慢）。需产品拍板。
