# 技术方案（研发）

## 锚点（真实入口/接口）

1. **开发调试入口**：`npm run dev`（Vite），桌面浏览器。
2. **手机验收入口**：`npm run build && npm run preview`，手机浏览器访问局域网地址；及 PWA"添加到主屏幕"后冷启动。两条入口都要走到（U3）。
3. **数据管线**：`scripts/parse_docx.py` 一次性解析 docx → `src/data/formulas.json`（构建期产物，运行时只读 import）。

## 技术栈

Vue 3 + Vite + Vant 4 + Pinia + vue-router + vite-plugin-pwa。样式用设计令牌 CSS 变量（见设计说明），字体 Noto Serif SC（系统宋体兜底，不依赖外网字体，保证离线）。

## 数据管线

- 解析：python-docx 读表格/段落，正则抽取 `【君】【臣】【佐】【佐使】【使】【功用】【主治】【歌诀】【注意】【用法】` 字段；出处取方名下一行《》文本。
- **容错**：字段缺失/跨行（已知案例：正柴胡饮用法断行）→ 该字段记 `null`，方剂仍入库；解析报告输出"缺字段清单"，人工抽样校对 20 方后入库。
- 输出 schema 见 `02-PRD与设计说明.md` 与设计文档 DESIGN.md §2.2。

## 记忆调度（简化 SM-2）

```jsonc
// localStorage: memoryMap[formulaId]
{ "rep": 0, "interval": 0, "due": "2026-11-10", "strength": 0 }
```

- 忘记 → rep=0, interval=0, due=今日
- 模糊 → interval=1, due=明日
- 记得 → interval 按 [1,2,4,7,15,30] 递进, strength+1
- 今日任务 = due ≤ 今日 的卡 + 每日新卡上限（默认 10）

## 失败与负面

- `formulas.json` import/解析失败 → 全局错误页（人话 + 重试按钮），try/catch 兜住，不白屏。
- localStorage 读写异常 → 捕获后重置为空进度并提示"学习记录已重置"，App 继续可用。
- 搜索：空输入不触发；无结果出空态文案。
- 所有含中文源文件以 UTF-8 写入；构建后 `npm run build` 零错误零警告。

## 禁止照搬（差异表预告）

- 《方剂通》方案的后端 API / PostgreSQL / Redis / 账号体系：**不抄**（本轮离线单机）。
- 借鉴保留：SM-2 字段模型、每日任务首页概念、三档自评。
- 阶段 0 mockups：仅作视觉参照，组件用 Vant 重写，不直接搬 HTML 进工程。
